# Phase 1 Audit — NEPO primitives ↔ Tailkit nearest-neighbors

Generated by `ck:plan` Phase 1. Every verdict cites concrete `file:line` evidence and a concrete Tailkit identifier fetched via the MCP.

## Methodology

1. Inventoried every export from `components/UI.tsx`, `components/shared/index.ts`, `design-system/index.ts`, `components/ui/`.
2. For each family, ran `mcp__tailkit__search_components` (falling back to `mcp__tailkit__browse_catalog` when search missed) and picked the closest 1-2 Tailkit identifiers.
3. Fetched one snippet (`a-c-empty-states-05`) in React to verify the retokenization cost concretely.
4. Scored: `KEEP` (NEPO at parity), `UPGRADE` (Tailkit adds real value), `MISSING` (NEPO has no equivalent), `N/A` (domain-specific, no Tailkit analog).

## Retokenization cost — confirmed by live fetch

Fetching `a-c-empty-states-05` (React) revealed the universal adoption tax:

| Tailkit idiom | NEPO translation |
|---|---|
| `border-secondary-200`, `text-secondary-300`, `bg-secondary-700` | `var(--line)`, `var(--ink-3)`, `var(--surface-3)` |
| `dark:border-secondary-700`, every `dark:*` variant | **deleted** (NEPO is light-only — `tokens.css:22`) |
| Heroicons inline SVG | `lucide-react` named imports (already a dep) |
| Hardcoded button classes (`border-emerald-700 bg-emerald-700 …`) | `<Btn variant="primary">` from `UI.tsx` |
| `bg-linear-to-b from-secondary-100 to-transparent` gradient | `var(--surface-2)` solid or a `--brand-grad` token |
| `text-2xl font-bold`, `text-sm/relaxed` | existing type tokens (`--fs-2xl`, `--lh-relaxed`) |

**Rough rule:** every Tailkit snippet needs ~30-60% of its lines rewritten to be NEPO-native. The structural JSX is reusable; the className soup is not. This is the single biggest finding of the audit and is the basis for the Phase 3 spike gate.

**Not adopted (KEEP):** Modal, Drawer, ConfirmDialog, Toast, Tooltip, Alert (inline), Breadcrumbs, Skeleton family, PlateTag, Money, all forms, DataTable (existing), Radix Select/DropdownMenu, Layout, PageHeader, Panel/Card, StatusPill/Badge/FilterPill, Spinner, LoadingOverlay, ErrorBoundary.

**Hard moves recommended for Phase 2 signoff:**
- **Definite:** T1 (cheap, high-impact), T3 (cheap, fills real gap).
- **Strong:** T4 (largest UX win for power users; cost is the concern).
- **Optional:** T2 (depends on whether a chart lib is acceptable — needs user signoff in Phase 2), T5 (good DRY but high blast radius), T6 (only if a real wizard-shaped feature lands soon — YAGNI otherwise), T7 (trivial but low value).

## Live MCP demo (the "see how it helps" deliverable)

The single `get_component_code(identifier="a-c-empty-states-05", tech="react")` call above produced a complete, working React snippet in one round-trip. That is the core value of the MCP: **inspiration + working starter code on demand**. The catch (also demonstrated above) is that ~30-60% of every snippet must be retokenized to NEPO tokens before it can ship.

**The MCP's real role:** a searchable design reference for the moments when "I'm building an empty state / banner / KPI / wizard and want to see what good looks like" — not a replacement for the existing design system.
