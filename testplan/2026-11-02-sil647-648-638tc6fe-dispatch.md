## 1. Root Cause Analysis (file:line)

### SIL-647 (id 752): Dispatch edit dialog density
- **Files & Lines:**
  - `frontend/src/features/dispatch/detailed-plan/DispatchPlanEditorCell.tsx` (~L405–430)
  - `frontend/src/features/dispatch/detailed-plan/DispatchPlanEditorCell.css` (~L210–235)
  - `frontend/src/features/dispatch/detailed-plan/AssignTruckGroupDialog.tsx` (~L282–315)
- **Root Cause & Why SIL-527 Density Law Did Not Cover Money Inputs:**
  1. SIL-527 introduced compact height and density constraints for standard inputs, but the planned revenue and planned carrier cost fields in `DispatchPlanEditorCell.tsx` used the shared `NumberField` component without specifying `controlSize="sm"`. In the design system, `NumberField` defaults `controlSize` to `'md'` (40px/44px).
  2. Inside `NumberField`, the input is wrapped in `.uui-input-wrap` with a dedicated `.uui-input-affix--suffix` ("đ"). Under `controlSize="md"`, the affix container renders with wide inline padding (`padding-inline: 10px`), large font, and a solid `--surface-2` background, visually bloating the money controls into oversized boxes.
  3. Furthermore, the parent CSS grid `.dispatch-assignment-dialog__fields` allocated 50% width tracks (`grid-template-columns: 1fr 1fr`), causing the "Nhà xe" and "Xe - biển số" selects to stretch across half the dialog width despite short content, wasting horizontal space.
- **Fix:**
  - Passed `controlSize="sm"` explicitly to both planned revenue and planned carrier cost `NumberField` controls in `DispatchPlanEditorCell.tsx`.
  - Added dedicated dense styles in `DispatchPlanEditorCell.css` for `.dispatch-assignment-dialog__field--money .uui-input-wrap`: `max-width: 150px`, `.uui-input-affix--suffix` with `font-size: 11px`, `padding-inline: 6px`.
  - Added compact width boundaries on `.dispatch-assignment-dialog__carrier` and `.dispatch-assignment-dialog__vehicle` (`max-width: 260px`).
  - Added `max-w-[260px]` to carrier and vehicle selects in `AssignTruckGroupDialog.tsx`.

### SIL-648 (id 753): PHÂN LOẠI column inline edit on detailed plan grid
- **Files & Lines:**
  - `frontend/src/features/dispatch/detailed-plan/DetailedPlanGrid.tsx` (~L800–845)
- **Root Cause:**
  - The PHÂN LOẠI column rendered purely static text formatted by `formatPlanClassificationLabel(row.dispatch.classification, row.dispatch.isCombined)` without an interactive trigger or inline editor. Changing classification required opening the full "Chỉnh sửa điều phối" dialog.
- **Fix:**
  - Replaced static text with an interactive button (`button.detailed-plan-grid__classification`) titled `"Nhấp để sửa phân loại"` to trigger inline editing.
  - Implemented inline edit popover/cell rendering `UuiSelectField` (conforming to `@tingting/no-native-select` rule) with options `Đơn` (SINGLE), `Kẹp` (DOUBLE), and `Kết hợp` (COMBINED).
  - Uses existing atomic plan update via `onAtomicSave(row, { classification: val })` (`PATCH /api/shipments/dispatch-detail-plan-rows/:fulfillmentId/plan`).
  - Provides optimistic update on selection, closes inline editor on success, and on error reverts and surfaces persisted error banner (`role="alert"`) and toast.

### SIL-638 TC6.2 (id 742): Soft weight warning visible and confirmable
- **Files & Lines:**
  - `frontend/src/features/dispatch/detailed-plan/useDispatchDetailPlan.ts` (~L430–455, ~L510–540)
  - `frontend/src/features/dispatch/detailed-plan/DetailedPlanGrid.tsx` (~L280–310, ~L340–370)
  - `frontend/src/features/dispatch/detailed-plan/DispatchPlanEditorCell.tsx` (~L210–235)
- **Root Cause:**
  - The backend returns HTTP 409 with error code `KEP_WEIGHT_WARNING` and exact message `"Tổng tải trọng hàng ước tính có thể vượt tải trọng cho phép của phương tiện, Điều vận vui lòng kiểm tra lại"` when cargo estimated weight exceeds vehicle payload for Kẹp configurations. The backend expects a retry with `kepWeightWarningConfirmed: true` to proceed.
  - The frontend previously swallowed or treated all 409 responses as generic ("Dữ liệu đã thay đổi. Vui lòng tải lại.") and never inspected `KEP_WEIGHT_WARNING`, never exposed `kepWeightWarningConfirmed`, and never rendered confirmation actions ("Vẫn lưu?" / "Hủy").
- **Fix:**
  - In `useDispatchDetailPlan.ts`, updated `savePlan` and `issueOrder` to inspect 409 responses for `code === 'KEP_WEIGHT_WARNING'` (or matching warning copy).
  - Maintained `pendingWeightWarning: { message, confirm, cancel }` state so the warning is surfaced with actionable confirmation. Calling `confirm()` resubmits with `kepWeightWarningConfirmed: true`; calling `cancel()` aborts cleanly.
  - In `DetailedPlanGrid.tsx`, updated the `role="alert"` banner to display the warning message alongside "Vẫn lưu?" (confirm) and "Hủy" (cancel) buttons when a weight warning is pending. Wrapped quick issue and inline classification edit handlers to catch weight warning and surface confirmation banner.
  - In `DispatchPlanEditorCell.tsx`, caught `KEP_WEIGHT_WARNING` during dialog save, prompted confirmation ("... Vẫn lưu?"), and on confirmation retried `attemptSave({ kepWeightWarningConfirmed: true })`.

## 4. Backend Contract Consumed & BE Gap Analysis

### Backend Contract Consumed for Weight Warning
- **HTTP Status:** `409 Conflict`
- **Error Code:** `KEP_WEIGHT_WARNING` (in `error.code` or `error.raw.code`)
- **Warning Copy:** `"Tổng tải trọng hàng ước tính có thể vượt tải trọng cho phép của phương tiện, Điều vận vui lòng kiểm tra lại"`
- **Confirmation Flag:** `kepWeightWarningConfirmed: true` (boolean)
- **Reference Implementation in BE:**
  - `backend/src/routes/shipments/core.routes.ts` (`POST /api/shipments/:id/dispatch` schema accepts `kepWeightWarningConfirmed: z.boolean().optional()`)
  - `backend/src/services/dispatch-resource-availability.service.ts`
  - `backend/src/services/dispatch-planning-commands.service.ts`

### Backend Gap Discovered
- **Endpoint:** `PATCH /api/shipments/dispatch-detail-plan-rows/:fulfillmentId/plan`
- **Schema:** `atomicDispatchPlanEditSchema` defined in `shared/src/schemas/index.ts`.
- **Finding:**
  - `atomicDispatchPlanEditSchema` is declared with `.strict()`, but does NOT currently list `kepWeightWarningConfirmed: z.boolean().optional()`.
  - While `fulfillmentDispatchSchema` (`POST /api/shipments/:id/dispatch`) includes `kepWeightWarningConfirmed`, the atomic plan edit schema in `shared/src/schemas/index.ts` will reject extra fields if sent to that specific endpoint unless updated.
  - The FE implements and forwards `kepWeightWarningConfirmed: true` across both `savePlan` and `issueOrder`. The BE lane owning shared schemas / plan routes should add `kepWeightWarningConfirmed: z.boolean().optional()` to `atomicDispatchPlanEditSchema`.
