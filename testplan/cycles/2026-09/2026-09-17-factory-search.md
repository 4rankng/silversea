# Factory search regression — shipment creation

Customer report: typing into **Nhà máy** on `/shipments/new` does not show results.

## Acceptance criteria (before implementation)

| Case | Reproduction | Expected |
|---|---|---|
| TC-CUS-FACTORY-SEARCH-01 | As CUS, choose a customer with factories. Open Nhà máy and type/paste an existing short/full name with leading, trailing or repeated spaces, mixed case and missing Vietnamese accents. Do not reopen the dropdown between edits. | Matching factories remain visible and selectable; name/address search normalizes Vietnamese accents, including đ, and whitespace. Pure regressions exercise the same predicate used by React Aria, with no second filter that can disagree or remove the selected item. |
| TC-CUS-FACTORY-SEARCH-02 | Search by factory code or words from name and address, including fields supplied through mapped searchText rather than the visible label. | Matching factories are shown, restricted to the selected customer's active factories. Option searchText (code/full name/address) is included through the rendered option text; matching results must never coexist with a contradictory no-results hint under the field. |
| TC-CUS-FACTORY-SEARCH-03 | Type an unmatched query, then backspace or replace it with a matching query while the input stays focused. Repeat with an existing free-text-enabled field. | Catalogue-only search keeps the dropdown open with exactly one “Không tìm thấy kết quả” status; matching results return immediately without another click. No factory ID is committed for unmatched text. Free-text-enabled fields commit and retain their custom text without forcing an unrelated option; reopening can offer catalogue alternatives and must not add a contradictory no-results warning. |
| TC-CUS-FACTORY-SEARCH-04 | Choose a filtered result using pointer and ArrowDown/Enter; blur, reopen, clear, then choose another factory. | Correct ID/short name and configured route are retained; keyboard and pointer use the same result list. |
| TC-CUS-FACTORY-SEARCH-05 | Switch customer; try another customer's factory name. Select a customer with no factories. | Previous factory is cleared. Unrelated factories never appear. Empty list has visible feedback; user can still use the existing create action. |
| TC-CUS-FACTORY-SEARCH-06 | Repeat filtering, no-match recovery and selection at 390px and 1440px; check LCL factory and warehouse pickers and neighboring customer/route/port controls. | Same search behavior, readable results, no new page overflow or clipped option selection. |
| TC-CUS-FACTORY-SEARCH-07 | Select a factory, reopen Khách hàng and select the same customer again without clearing. Repeat with an LCL shipment; then switch to another customer. | Same-customer selection preserves the factory catalog and chosen values. Changing customer clears FCL/LCL factory IDs and factory-derived routes; independent manual routes remain available. |
| TC-CUS-FACTORY-SEARCH-08 | With a configured factory route or an independently selected manual route, change customer in FCL and LCL. | Clear factory-derived routes; preserve an independent manual route. Saved payloads have no factory ID from the previous customer. |
| TC-CUS-FACTORY-SEARCH-09 | Create a factory inside FCL/LCL intake or a warehouse inside LCL intake. Delay or fail the subsequent catalogue reload. | The successful creation response immediately supplies the selected short name, details and inherited route. The selected value never appears blank while the catalogue refreshes; its ID is retained in the shipment. Unit tests cover delayed refresh; browser checks cover actual create/close and visible selection. |
