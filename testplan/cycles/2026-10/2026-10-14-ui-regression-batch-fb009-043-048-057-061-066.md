## Case 2026-10-14-B1 — FB-009 copy-time button (clipboard + "Đã copy" toast)

- Repro: on /shipments/new rows and the CUS workboard ledger rows a clerk
  wants to copy a container's giờ hẹn (appointment time) out to another app.
  The only copy affordance is copy-down-to-empty-rows, which renders solely
  when a sibling row lacks a schedule (`emptyAppointmentCount >= 1`) — the
  recurring "mất hẳn" complaint (rounds 4/13/14) is that button existing only
  in that state. No clipboard copy of the time itself exists anywhere.
- Root cause: the copy affordance is conflated with the fill-siblings action;
  a plain "copy this time" (clipboard + toast) was never built.
- Expected: a per-row copy-time button beside the appointment value on both
  canonical FB-009 surfaces (create-form "Ngày giờ đóng trả" cell + CUS
  ledger "Giờ hẹn đóng/trả" cell), following the house `CopyCodeButton`
  pattern (clipboard API + execCommand fallback, icon flips to check). On
  success a toast reads `Đã copy giờ hẹn <time>`. Rendered whenever the row
  holds a committed appointment — never gated on sibling rows.

## Case 2026-10-14-B2 — FB-043 dispatch-table uniform row-height contract

- Repro: /dispatch-detail rows go uneven whenever a column share drops below
  its content floor — assigned rows towered 164–198px beside 97px unassigned
  (R22 regression, ticket 141026001010 round 18). Fixed twice by colgroup
  percentage rebalances; the defect class survives any future rebalance.
- Root cause (system): nothing bounds row height. Cells wrap freely
  (`white-space: normal !important`, `overflow-wrap: anywhere`), so any cell
  whose content outgrows its column dictates a taller row.
- Expected (component-level contract, desktop table only — the ≤900px card
  layout keeps its own shape):
  - every body row renders at one fixed height (`--dpg-row-h`);
  - every cell clips (`overflow: hidden`) with each `__line` on one line
    (`white-space: nowrap; text-overflow: ellipsis`), full text carried by
    `title`;
  - cell padding comes from the spacing scale (`--space-*`), not raw px;
  - the notes cell keeps its expand-dialog escape hatch; interactive
    controls (Sửa/Phát lệnh) stay fully inside the fixed height.
- Pins: a styles contract asserting the fixed height, per-line ellipsis,
  clipping, spacing-scale padding, and card-band reset.

## Case 2026-10-14-B3 — FB-048 red danger border on invalid states (UUI select)

- Repro: any `UuiSelectField` marked `invalid`/`error` (e.g. a required
  select failed validation) shows a neutral border at rest; the red boundary
  appears only while the control is focused or its menu open, then reverts.
  Native `.input` fields and `SearchableSelect` paint red at rest via
  `.input[aria-invalid="true"]` / QA-AUDIT-UI57; the vendored UUI select
  trigger is the odd one out and never sets `aria-invalid`.
- Root cause: `components/untitled-ui/base/select/select.tsx` gates its
  `border-error` on `isInvalid && (isFocused || isOpen)` and sets no
  `aria-invalid`, so the base.css public invalid paint cannot catch it.
- Expected: an invalid select trigger paints the danger border at rest,
  keeps the stronger red outline while focused/open, exposes
  `aria-invalid="true"` for the QA-AUDIT-UI57 house paint, and the error-wins
  rule (no brand ring on an invalid control) is preserved.

## Case 2026-10-14-B4 — FB-057 topbar search responsive width

- Repro: the global topbar search sits at 360px on every desktop viewport —
  starved on wide screens (round-14 ruling relaxed focus to 560px, still a
  hard cap).
- Expected (owner ruling, this batch): min 360px on the desktop bar; from
  1280px viewport up it grows fluidly with the free topbar space — no hard
  max-width cap at any width; the ≤1023px mobile tiers keep their smaller
  minimum (the phone bar cannot hold 360px).

## Case 2026-10-14-B5 — FB-061 demo seed gated out of production

- Repro: FB-061 history — QA/staging surfaces repeatedly showed self-authored
  seed rows (invoice-tracking card 376 cleanup, 2026-10-08). `pnpm seed`
  (backend/src/seed.ts) inserts the full demo dataset (demo users, trucks,
  shipments, trips, bulk rows, AR/AP fixtures) and nothing stops it from
  running against a production database (`NODE_ENV=production` compose).
- Expected: the demo seed refuses to run when `NODE_ENV=production` unless
  `SEED_DEMO_DATA` is an explicit opt-in flag; the refusal is loud (names
  `seed:prod` as the production path). Local dev/test seeding is unchanged.

## Case 2026-10-14-B6 — FB-066 quick-add on trip-create vehicle/driver selectors

- Repro: card 121026141040 — /trips/new "Xe đầu kéo *" and "Lái xe" selects
  have no quick-add; a dispatcher meeting a new plate/driver must leave the
  form for the catalogs. Round 16 ruled it "by design"; the owner now

  route-scoped POST on /trucks + /drivers; other roles see the API error in
  the dialog.
