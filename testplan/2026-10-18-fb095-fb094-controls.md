## FB-095 — badge "Lẻ · Ghép (i/N)" trên /dispatch-detail không có control hủy ghép

### FB095-UI-01 — badge là control mở menu nhóm (Xem nhóm / Hủy ghép)
- **Repro**: /dispatch-detail, hàng lô lẻ đã ghép nhóm (badge "Lẻ · Ghép (1/2)").
  QA bấm/hover badge → chỉ hiện tooltip, không có action.
- **Kỳ vọng**: badge là button (giữ nguyên tooltip); bấm mở popup "Nhóm ghép trả
  ĐV · Lẻ (i/N)" hiển thị thành viên nhóm (Xem nhóm: BKS, loại xe, danh sách
  Lô i · Số Bill/Booking) kèm action "Hủy ghép".
- **Test**: `DetailedPlanGrid.fb095-badge.test.tsx` (mở menu, thấy thành viên,
  chọn "Hủy ghép" → gọi `onUnmergeLclLot` với payload đúng; badge giữ dạng
  text tĩnh khi trang chưa nối callback — parity với nút "Tách nhóm").

### FB095-UI-02 — confirm guard trước khi hủy, copy nêu thăng cấp Lô 2
- **Repro**: QA kỳ vọng "hủy ghép phải an toàn (chuyển quyền Lô chính + 100%
  tiền theo spec)" — spec §4: Hủy ghép / Xóa Lô 1 → Lô 2 thăng cấp Lô chính.
- **Kỳ vọng**: trước khi gọi API có Modal confirm
  "Hủy ghép nhóm N lô? Lô 2 sẽ thành Lô chính và nhận 100% tiền cước trả ĐV."
  (N = 2 kèm "Nhóm giải tán vì chỉ còn một lô."); hàng không phải Lô 1 → copy
  "Lô 1 giữ nguyên 100% tiền cước trả ĐV; lô này trở về cước trả ĐV riêng."
  Hủy confirm → không có lời gọi API nào.
- **Test**: `DispatchDetailPlanPage.lcl-unmerge.test.tsx`.

### FB095-UI-03 — xác nhận → POST /shipments/lcl/unmerge (COST) + toast + refresh lưới
- **Kỳ vọng**: xác nhận gọi `unmergeLclLot({ shipmentId, dimension: 'COST' })`
  (route `POST /api/shipments/lcl/unmerge`); toast nêu Bill kế vị nhận 100%
  cước trả ĐV (hoặc "nhóm giải tán"); lưới tải lại (`detailPlan.refresh()`).
  Server từ chối (nhóm đã chốt kế toán) → toast lỗi nguyên văn, không refresh.
- **Test**: `DispatchDetailPlanPage.lcl-unmerge.test.tsx`.

### FB095-UI-04 — không thêm control vào dialog điều phối (giới hạn phạm vi)
- **Kỳ vọng**: QA chấp nhận "trên badge nhóm HOẶC trong dialog điều phối" —
  badge menu (FB095-UI-01..03) phủ acceptance. `AssignTruckGroupDialog` /
  "Chỉnh sửa điều phối" (DispatchPlanEditorCell) giữ nguyên — ngoài phạm vi.
- **Test**: không test mới (không hành vi mới); ghi nhận ở coverage.

## FB-094 — /accounting/chot-debit thiếu nút "Xuất Debit Note"

### FB094-UI-01 — nút "Xuất Debit Note" trên toolbar
- **Repro**: toolbar chot-debit chỉ có "Xác nhận đối soát" / "Chọn Debit" /
  "Đối soát" / "Hoàn tác" / "Cột hiển thị" — không có nút xuất.
- **Kỳ vọng**: toolbar (FilterBar actions) có nút "Xuất Debit Note", disable khi
  chưa chọn dòng (title giải thích), enabled theo dòng đang chọn.
- **Test**: `AccountingDebitClosePage.export.test.tsx`.

### FB094-UI-02 — click → tạo/ghép Debit Note + tải file (blob + a[download])
- **Kỳ vọng**: click gọi `createDebitNoteBatch(ids, idempotency-key ổn định theo
  selection)` (`POST /api/shipments/debit-notes`) rồi
  `exportDebitNoteFile(ids[0], documentId)` (`GET /api/shipments/:id/debit-note/export?documentId=`),
  tải `giay-bao-no-<Số Bill/Booking>.xlsx` qua `URL.createObjectURL` + anchor
  download (pattern của `ShipmentDebitPage.exportSelectedLockedLots`), revoke
  object URL, message thành công.
- **Test**: `AccountingDebitClosePage.export.test.tsx`.

### FB094-UI-03 — lỗi server hiện nguyên văn, không giả success
- **Kỳ vọng**: POST/GET lỗi → message banner `role="alert"` nguyên văn thông điệp
  server (vd 409 "lô đã nằm trong Debit Note đã xuất"), không tải file.
- **Test**: `AccountingDebitClosePage.export.test.tsx`.
