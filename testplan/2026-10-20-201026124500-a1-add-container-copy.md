### Root cause (both layers, confirmed)

1. **Seeding whitelist** — `addFieldsSeed` copies only
   {containerTypeId, cargoWeightKg, customerAppointmentAt}; A.1's Tuyến/Nhà
   xe/Nâng/Hạ never enter the new-row draft (the add row renders them blank).
2. **Nhà xe has no copy path anywhere** — the add wire carries no carrier, the
   insert inherit covers container columns only, and the new fulfillment is
   born without planned carrier fields. (Round-1's verify-fail pass was a
   false positive here: its `inheritOk` never checked carrier.)

### Fix (data-flow, no label changes)

- FE seeding (`AddContainerFields`/`addFieldsSeed`/`CusContainerAddRow`):
  extend the seed to the full A.1 set — routeId/name, lift/drop (ids guarded
  against the ports catalog), carrier identity/name, weight, appointment —
  rendered as seeded cells in the add row and sent on submit. Loại cont seed
  DROPPED (191026100000's type seed is superseded by this ticket's restated
  law: Loại cont stays operator entry); the submit sends containerTypeId
  explicitly (pick or null) so the wire's inherit can't re-introduce it.
- Wire (`shipmentCusContainerAddSchema`): + `carrierType` / `externalCarrierId`
  (nullable-optional, paired like the line-update schema).
- BE (`addCusShipmentContainer`): resolve the added row's carrier plan —
  provided value or first non-null sibling FULFILLMENT's planned carrier —
  and stamp it on the new fulfillment (`createFulfillmentForAddedContainer`).
  Biển số/xe KHÔNG copy (ngoài danh sách A.1). Column inherit for route/lift/
  drop unchanged (wire fallback contract).
