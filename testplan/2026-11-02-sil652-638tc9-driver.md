# Test Plan & Evidence — SIL-652 (id 758) + SIL-638 TC9/TC4 (id 742)

## 1. Root Cause Analysis

### SIL-652 (id 758) — Dead Accept Button on Locked L2 Trip Detail
- **Location**: `frontend/src/pages/DriverTripDetailPage.tsx:392-396` (lines 392-396 on main prior to fix) and `showAcceptStickyBar` at line 636.
- **Root Cause**: The detail page's accept predicate was purely based on `milestoneActionState(Boolean(acceptEvent), nextMilestoneIndex, 0)` checking whether the `ORDER_RECEIVED` milestone was recorded. It completely omitted the pair-lock predicate `card.pairLocked` from `useDriverJourneyBoard()`, which the journey list (`DriverTripsPage.tsx:257-265`) uses to hide the action footer and display `"Cần hoàn thành trả hàng lệnh trước để mở khóa"`. As a result, the detail page for an L2 (locked KẾT HỢP pair) order still rendered the "Nhận lệnh vận chuyển" button. When the driver tapped it, the action was rejected by backend or did nothing while leaving the trip `CREATED`. The list and detail contradicted each other, violating the house law against dead buttons.

### SIL-638 TC9 (id 742) — Complete Transport Order Without e-POD
- **Location**: `frontend/src/pages/DriverTripDetailPage.tsx:665-677` and `frontend/src/features/driver/driver-trip-model.ts:57-69`.
- **Root Cause**: The sticky footer button on the trip detail page is labeled `"Hoàn tất lệnh vận chuyển"` (`completeCtaLabel(trip.status)` for `IN_TRANSIT`). However, its click handler was merely `onClick={() => navigate('/my-trips/' + validTripId + '/pod')}`. It never completed the trip or prompted confirmation. In commit `3ee6e5d8`, a unit test was only added to `DriverTripPodPage.test.tsx` mocking an existing DRAFT and clicking `HOÀN THÀNH CHUYẾN`, which completely bypassed the real user path. When QA opened trip 143 (`IN_TRANSIT`) on `DriverTripDetailPage` and tapped `"Hoàn tất lệnh vận chuyển"` with 0 photos uploaded: no dialog appeared, no toast appeared, and the trip stayed `IN_TRANSIT` with "no other completion path found". Per owner ruling (31/10), e-POD is optional for TC9 ("không chặn vì thiếu ảnh/phiếu hạ bãi").

## 4. Backend Gap Analysis for "Unlock L2 on Completion"

**Analysis Result**: **NO backend gap exists.**
- In `backend/src/services/driver-fulfillment.service.ts` (`completeOwnedFulfillmentTrip`):
  When L1 completes, post-accept milestones (`DRIVER_FULFILLMENT_PROGRESS_SEQUENCE`) are inferred and recorded, and the trip status transitions to `TripStatus.COMPLETED`.
- In `backend/src/services/driver-journey-board.service.ts`:
  The `pairLocked` field for L2 is calculated as:
  ```ts
  pairLocked: pairActive
    && pair!.pairKind === 'KET_HOP'
    && pairOrder === 2
    && firstTripId != null
    && !isTripFinished(firstTripId)
  ```
  `isTripFinished(firstTripId)` checks if L1 is `COMPLETED`. When L1 transitions to `COMPLETED`, `isTripFinished(firstTripId)` evaluates to `true`, causing `pairLocked` to evaluate to `false` immediately.
- Frontend invalidates `qk.driver.journeyBoard` and `qk.driver.twoOrders` upon completion before navigating back to `/my-trips`, so the cache is invalidated and the journey list renders L2 unlocked immediately.
