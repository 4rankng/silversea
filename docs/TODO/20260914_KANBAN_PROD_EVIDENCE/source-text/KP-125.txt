Show a compact status on every advance request
QA-041 | P3 | Enhancement | TODO
Environment: Staging https://vantai.tingting.vip
Reviewed: 14 September 2026
Role: Ops, hoangnh (Nguyễn Huy Hoàng); Chrome desktop and mobile
Page: https://vantai.tingting.vip/my-advances
Existing behaviour
The Tất cả list shows three advance requests without explicit status labels on individual rows. The pending 12,345 and 50,000 VND requests show only amount, date and purpose. The approved 75,000 VND request is distinguished indirectly by approver metadata. Desktop and phone show this gap. The Chờ duyệt 2 filter correctly returns the two pending requests.
Target behaviour
Display a short textual status on every advance row or card, using the existing status vocabulary. Place it within the current compact layout, keeping amount and purpose easy to scan and approval metadata secondary.
Impact
Users must switch filters or infer status from absent metadata to identify requests awaiting approval in a mixed list.
Cause and investigation
Design hypothesis: status is communicated at summary and filter level but omitted from each record. Confirm the row or card rendering; no incorrect stored state or approval-policy defect is established.
Steps to reproduce
1. As Ops, open Yêu cầu Tạm ứng and select Tất cả. Inspect the three captured requests at desktop width.
2. Select Chờ duyệt 2: the 12,345 and 50,000 VND requests appear. Return to Tất cả and compare their row labels with the approved request.
3. Repeat at 390 × 844 and scroll through the cards. Approval is indicated only by approver metadata, while pending cards have no explicit state.
Acceptance criteria
1. Every row or card shows its actual status in text, including the All view; status remains consistent with filters and counts.
2. Use a compact label or badge within existing space at desktop, tablet and mobile widths; do not add taller cards or oversized text.
3. Retain approval metadata. Where a rejected state and reason exist, make the reason accessible without expanding every row by default. No rejected fixture was exercised.
Requirement reference
Exploratory staging review, 14 September 2026.
User direction: professional, compact, data-heavy UI across desktop, tablet and mobile.
