Existing behaviour
Account editing rejects invalid email and short password, but shows raw English schema messages in a global banner; password also gets Vietnamese inline feedback. Trip-expense settings reject −400001 in Tiền kết hợp mặc định (đ), but show “defaultDriverSalary: Number must be greater than or equal to 0” beside Save. The internal field name does not match the visible label.
Target behaviour
Use concise Vietnamese messages beside the affected fields, with accessible associations and first-error focus. Any summary should use visible field labels and avoid raw schema names or duplicate technical messages.
Impact
Administrators must translate technical messages and locate the corresponding field before correcting input.
Cause and investigation
Validation feedback is presented inconsistently across the observed forms. Review message mapping and placement; shared implementation is not established.
Steps to reproduce
1. In /users, edit qa.audit.manager.0914; enter not-an-email and save.
2. Add a new password shorter than six characters; save and compare global and inline feedback.
3. In /config/trip-expense, enter -400001 in Tiền kết hợp mặc định (đ) and save.
4. Correct the invalid values and verify error clearing and successful save.
Acceptance criteria
1. Provide Vietnamese field messages for Email, Mật khẩu mới and Tiền kết hợp mặc định using their visible labels.
2. Associate and announce validation feedback, focus the first invalid field and preserve unrelated input.
3. Clear resolved errors and avoid duplicate or contradictory summary and inline messages.
4. Retain rejection rules and supported blank optional email; retest combined errors and correction on desktop, tablet and phone.
Requirement reference
Observed invalid account inputs and negative trip-expense default; all were correctly rejected.
