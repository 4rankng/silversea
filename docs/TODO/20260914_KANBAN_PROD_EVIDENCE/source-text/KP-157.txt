Honor an explicit zero road allowance override
QA-128 | P2 | Bug | TODO
Review date: 14 September 2026
Scope: Local source snapshot 9e09c901f5f7
Role: Authorized trip editor; shared cost calculation
Location: /trips/:id/edit → PUT /api/trips/:id/pre-departure or /actuals
Existing behaviour
The edit field says only a blank value means automatic calculation. Its payload preserves numeric zero, and the schema accepts nonnegative overrides. However computeTripTotals uses an override only when it is greater than zero. A local execution of the exact production function with a 500,000 VND computed allowance returned allowance/cost 500,000 and profit 500,000 for both null and explicit 0; a 100,000 override worked. Revenue was 1,000,000 and other costs were zero.
Target behaviour
Treat null/undefined as automatic and every valid nonnegative override, including zero, as explicit. Preserve the selected amount through save, readback, recalculation and totals.
User impact
An operator cannot remove the allowance by entering zero. Trip cost remains overstated and gross profit understated by the computed allowance; the stored override can disagree with the derived amount.
Cause and investigation
shared/src/calculations/tripTotals.ts:140–143 requires roadAllowanceOverride > 0. The schema/UI contract distinguishes absent from zero, so this extra condition silently discards a valid correction. The resulting allowance enters totalCost at lines 195–198.
Steps to reproduce
1. In a controlled fixture, use an editable OWN trip whose automatic road allowance is 500,000, with no tolls, bonus or other allowance modifiers.
2. Enter 0 in Điều chỉnh tiền đi đường, retain valid legs/required fields and submit through the normal edit flow.
3. Compare override and totalRoadAllowance after save/reload. Source trace predicts override 0 but allowance 500,000; browser/API reproduction remains to be run. The isolated calculation already reproduces this discrepancy.
Acceptance criteria
1. Use the explicit override whenever it is non-null and valid, including zero. Keep ordinary negative/invalid input validation.
2. Add pure calculation cases for null, undefined, zero and positive overrides against a positive automatic allowance; assert totalRoadAllowance, totalCost and grossProfit.
3. Add edit/save/readback coverage for zero, then clear to automatic and confirm the automatic amount returns. Retain direct authorized saves without adding approval stages.
Verification coverage
CODE-READ ONLY. The source path was reviewed; the current staging deployment, UI interaction and database side effects were not exercised for this finding. Add a testplan regression before implementing and exercise the stated recovery and permission boundaries.
