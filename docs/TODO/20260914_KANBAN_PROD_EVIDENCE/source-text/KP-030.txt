Reconcile drop off destinations across driver trip views
QA-004 | P1 | Bug | TODO
Environment: Staging https://vantai.tingting.vip
Reviewed: 13 September 2026
Role: Driver bqhuong; Chrome phone viewport 390 by 844, 13 September 2026
Page: https://vantai.tingting.vip/my-trips and /my-trips/20
Existing behaviour
The accepted card for TSTU4182600 shows HẠ Bãi JJ LOGISTICS. Opening its detail page /my-trips/20 shows Cảng hạ NEWEB-1. The customer-service container ledger also shows Bãi JJ LOGISTICS for this container. These screens label different destinations as the drop-off port for the same trip.
Target behaviour
Use the same authoritative destination for the same journey stage. If one value is the delivery factory and another is the empty-container return depot, show both with distinct stage labels rather than labeling both Hạ or Cảng hạ.
Impact
A driver could follow the wrong destination depending on which screen is read. Prioritize reconciliation before release.
Cause and investigation
Possible inconsistent mapping of fulfillment destination, factory and return-depot fields. The authoritative intended destination must be checked in the shipment model; this review establishes the display inconsistency only.
Steps to reproduce
1. Sign in as bqhuong, select Đã nhận and locate TSTU4182600.
2. Read HẠ on the card: Bãi JJ LOGISTICS.
3. Open Xem chi tiết and expand Thông tin lệnh. Read Cảng hạ: NEWEB-1.
Acceptance criteria
1. Card, trip detail and customer-service view agree on each named journey stage.
2. Factory delivery and depot return remain distinct when both exist.
3. Verify both import and export examples with different factories and depots.
