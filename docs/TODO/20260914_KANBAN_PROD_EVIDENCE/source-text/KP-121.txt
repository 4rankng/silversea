Persist clearing of optional truck text fields
QA-132 | P2 | Bug | QA_PASSED
Review date: 14 September 2026
Scope: Local source snapshot 9e09c901f5f7
Role: Admin editing an existing truck
Location: https://vantai.tingting.vip/fleet and /fleet/vehicles — Sửa xe
Existing behaviour
Clearing Loại hình xe, Hãng xe or Ghi chú causes the form to submit undefined for vehicleClass, brand or note. JSON serialization removes those properties. The backend applies only supplied properties, so a successful update retains the old stored text and it returns on reload. The same form already sends null when clearing numeric and date fields. Existing version and idempotency transport guards do not restore the omitted fields.
Target behaviour
Represent an intentional clear with the supported explicit null value, while preserving any deliberately untouched fields. Reopened and reloaded truck data must match the saved blank form.
User impact
Users cannot remove obsolete or incorrect truck metadata through the editor, even when a save reports success.
Cause and investigation
Confirmed source mismatch: empty text becomes undefined in the form; the JSON payload therefore expresses omission, while the partial update correctly leaves omitted database fields unchanged. The schema already supports null.
Steps to reproduce
1. Proposed regression: create or use an owned truck fixture with nonempty vehicle class, brand and note. Open Sửa xe as Admin after its data loads.
2. Clear one field, save with a current record version, then reopen and reload. Repeat for all three fields and for clearing them together; inspect the serialized request and readback.
3. Repeat from both /fleet and /fleet/vehicles, without altering plate or trailer assignment.
Acceptance criteria
1. Each intentionally cleared text field is sent as explicit null and remains blank in API readback and both editors after reload.
2. Nonempty text remains trimmed where appropriate. Unchanged metadata and carrier/trailer relationships remain intact.
3. Add a component/serialization test for clear versus unchanged values and an API persistence regression using the existing nullable schema. Retain optimistic concurrency and idempotency guards.
4. Verify clearing and saving at phone, tablet and desktop widths; no additional field or oversized control is needed.
