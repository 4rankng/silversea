Keep customer service rows compact with concise missing data summaries
QA-015 | P2 | Enhancement | TODO
Environment: Staging https://vantai.tingting.vip

Role: CUS — Đinh Công Thành; login thanhdc; Chrome desktop 1728 × 929

Existing behaviour
The QATU0900038 and QATU0900043 rows show long missing-field lists in narrow yellow status panels. Wrapping makes each row about 180px tall, leaving much of the adjacent cells empty. This finding concerns row height, not the empty page below two filtered results.
Target behaviour
Keep the workflow state and key dispatch blocker visible in a compact summary. Provide a missing-field count and a clear details control for the complete list and relevant editing destination. Use readable text and content-driven row height.
Impact
Repeated warning lists reduce the number of visible containers and slow ledger scanning.
Cause and investigation
Design hypothesis: full explanations in a narrow status cell determine the height of the whole row. No code diagnosis was performed.
Steps to reproduce
1. As thanhdc, open Chi tiết lô hàng at 1728 × 929 with incomplete containers missing several fields. The observed QATU0900038 and QATU0900043 fixtures later changed.
2. Compare the tall Chưa cập nhật lists with neighboring container, location and schedule values.
Acceptance criteria
1. Incomplete rows use less vertical space at the same viewport while container identity, schedule, assignment and key blocker remain readable.
2. A labeled details control exposes every missing field and its editing destination by mouse, keyboard and touch; its count matches the list.
3. Critical dispatch blockers remain visible without opening details; secondary metadata does not dominate row height.
4. Long names and expanded notes wrap naturally without clipping or overlap. Do not shrink text or hide required information to increase density.
Requirement reference
User UI/UX direction, 13 September 2026: professional, compact, data-heavy presentation.
The UI waste lots of space-data-intensive-design.docx: related density intent, applied here to the customer-service ledger.
