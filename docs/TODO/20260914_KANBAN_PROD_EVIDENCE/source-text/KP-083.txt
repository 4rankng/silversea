Fix expense creation buttons for accountants
QA-039 | P2 | Bug | TODO
Environment: Staging https://vantai.tingting.vip
Reviewed: 14 September 2026
Role: ACCOUNTANT; hoapt (Phạm Thị Hòa); Chrome desktop 1440×900
Page: /expenses → /accounting
Existing behaviour
The accountant can open Chi phí phát sinh at /expenses. The empty list offers two enabled Thêm phiếu chi buttons: one in the toolbar and one in the empty state. Clicking either button independently redirects to the accounting work queue at /accounting. No expense form opens, and no explanation of a permission restriction or failed action appears.
Target behaviour
Make both buttons consistent with the intended accountant policy. If creation is permitted, open the expense form with a usable return path. If creation is restricted, hide the unavailable action or disable it with a clear explanation. Preserve the intended permissions.
Impact
The accountant follows an advertised creation action and loses the expense context without learning how to proceed.
Cause and investigation
Hypothesis: the button destination and route access rules are misaligned. Confirm the intended role policy and inspect navigation and guards; no implementation cause or permission entitlement is established.
Steps to reproduce
1. Sign in as hoapt and open /expenses through Chi phí phát sinh. Use the observed empty-list state.
2. Click the toolbar Thêm phiếu chi. Observe navigation to /accounting with no form or explanation.
3. Return to /expenses and click Thêm phiếu chi in the empty state. Observe the same result.
Acceptance criteria
1. Both entry points follow the same intended role policy. An enabled creation action opens its form; restricted users receive an accurate unavailable state.
2. For an authorized role, verify required-field validation, save and reload, plus cancel/back navigation to the expense list with its context retained.
3. For a restricted role, enforce the policy on direct navigation as well as buttons, and explain denial without silently redirecting to an unrelated page.
4. Check empty and populated lists on mobile, tablet and desktop, including keyboard activation and accessible explanations. Do not broaden account permissions merely to make the button work.
Requirement reference
Full-app Chrome audit, 14 September 2026; both expense creation buttons were exercised independently.
