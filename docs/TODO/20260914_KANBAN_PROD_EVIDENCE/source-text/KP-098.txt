Keep the session active after an incorrect current password
QA-063 | P2 | Bug | TODO
Environment: Staging https://vantai.tingting.vip
Reviewed: 14 September 2026
Role: Manager qa.audit.manager.0914; desktop 1440 × 900
Page: Menu người dùng → Đổi mật khẩu; unexpected redirect to /login
Existing behaviour
Submitting an incorrect current password with matching valid new-password fields closes the dialog and redirects to login. The page says Phiên đăng nhập đã hết hạn. Vui lòng đăng nhập lại để tiếp tục. Reproduced twice, including within 30 seconds of a fresh login. The existing password still worked when signing back in after the first attempt.
Target behaviour
Keep a valid session active and show an inline current-password error. Clear and focus the incorrect sensitive field so the user can retry. Use session-expired feedback and reauthentication when the session has actually expired.
Impact
A typing mistake interrupts the whole session and gives the wrong recovery explanation. Users must sign in again without knowing whether the password changed.
Cause and investigation
Global authentication-error handling may treat failed current-password verification as session expiry. Check the response contract and dialog handling; neither code nor the response status was inspected.
Steps to reproduce
1. Sign in successfully, then immediately open Menu người dùng → Đổi mật khẩu.
2. Enter an incorrect current password and a matching valid new password and confirmation. Submit Đổi mật khẩu.
3. Observe the redirect to /login and expired-session message. Sign in using the unchanged existing password.
Acceptance criteria
1. An incorrect current password produces a field-specific error without ending a valid session or changing the password.
2. The dialog supports correcting the value and retrying, with keyboard focus and accessible error announcement. Do not expose password values.
3. A genuinely expired session still follows the intended reauthentication flow with an accurate message.
4. Retest empty fields, mismatched new passwords, wrong current password and a successful change on phone, tablet and desktop. Existing empty and mismatch validation must remain intact.
Requirement reference
Staging Chrome audit, 14 September 2026. User requirement: clear validation and recoverable unsuccessful flows.
