Resolve road allowance using the newly selected trailer type
QA-130 | P2 | Bug | TODO
Review date: 14 September 2026
Scope: Local source snapshot 9e09c901f5f7
Role: Authorized trip editor
Location: /trips/:id/edit → PUT /api/trips/:id/pre-departure or /actuals
Existing behaviour
When trailer type changes, the service initially looks up the new type correctly. If that rate is missing or zero, a later fallback queries the previous trip.trailerType instead. For a 40FT trip changed to 20FT on a route with a positive 40FT allowance but no 20FT rate, the old 40FT amount is restored and fed into the new trip's totals. The same overwrite occurs when the 20FT rate is explicitly zero.
Target behaviour
Resolve the allowance from the final route and final trailer type consistently. Keep an explicit zero distinct from a missing rate. If missing configuration requires intervention, expose that condition; never silently borrow the old trailer type's rate.
User impact
The saved trip can show 20FT while its allowance, total cost and gross profit use the 40FT rate. Users cannot trust recalculated expenses after an equipment correction.
Cause and investigation
trip-figure-updates.service.ts:240–249 resolves finalTrailerType, then lines 301–310 treat zero as unresolved and query trip.trailerType. The fallback ignores the newly selected type and conflates configured zero with missing data. The resulting base enters computeTripTotals at lines 442–467.
Steps to reproduce
1. Prepare an editable OWN trip on route R with trailer type 40FT and a 500,000 VND 40FT road-allowance rate; leave the 20FT rate absent, with no manual override or toll modifiers.
2. In the trip editor change Loại rơ moóc to 20FT, keep route R and valid required data, and save.
3. Read the new trailer type, applied allowance and totals. Source trace predicts 20FT with the 40FT rate of 500,000. Repeat with an explicit 20FT zero rate. Runtime reproduction remains pending.
Acceptance criteria
1. Use the final route/trailer pair for all allowance resolution and persistence. Do not run a fallback for the obsolete trailer type.
2. Represent missing rate separately from a valid zero; decide the supported missing-rate behavior explicitly and keep user feedback accurate.
3. Add service/API regression cases for 40FT→20FT and reverse, with new-type positive, zero and missing rates; also change route and trailer together.
4. Assert trailer type, roadAllowanceBaseApplied, totalRoadAllowance, totalCost and grossProfit after reload; retain existing valid manual overrides and direct authorized editing.
