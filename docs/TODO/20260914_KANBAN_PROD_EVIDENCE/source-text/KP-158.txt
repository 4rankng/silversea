Synchronize actual work days when the driver completes a trip
QA-129 | P2 | Bug | TODO
Review date: 14 September 2026
Scope: Local source snapshot 9e09c901f5f7
Role: Driver; payroll users
Location: POST /api/driver/me/fulfillments/:fulfillmentId/complete → /salary
Existing behaviour
Driver acceptance synchronizes attendance with a null arrival date, which writes only the departure day. Driver completion directly transitions the trip to COMPLETED, records the completion timestamp and posts financial data, but neither its route nor service synchronizes the completed date range. Its post-commit work only invalidates reports. Payroll reads stored work-day rows, so later trip dates remain their previous state or default standby/Sunday off.
Target behaviour
A successful driver completion must reliably synchronize every actual business-date work day through the completion date, using the same attendance authority as other supported completion paths. Retries must converge without duplicate days or financial posting.
User impact
A multiday trip can show only one trip day in payroll. Missing weekdays are misclassified as standby; a worked Sunday or previously marked leave date can reduce paidDays and net salary. The effect is conditional on the omitted dates, not a claim that every overnight trip reduces pay.
Cause and investigation
completeOwnedFulfillmentTrip ends with report invalidation at driver-fulfillment.service.ts:494–497. The route at driver.ts:512–535 does not add attendance work, and transitionTripStatus has no attendance call. Acceptance's separate helper passes arrival=null at driver-fulfillment.service.ts:241–247. syncTripWorkDays uses arrivalDate || departureDate at attendance.service.ts:208.
Steps to reproduce
1. Prepare an assigned OWN fulfillment that departs Saturday and finishes Sunday, with an open payroll period and no other trip covering Sunday. Use a positive base salary.
2. Accept as its driver, provide valid completion evidence, then complete through the driver fulfillment endpoint/UI.
3. Read trip completedAt and both attendance dates/payroll. Source trace predicts completion succeeds while only Saturday is TRIP_DAY and Sunday remains WEEKLY_OFF. This runtime scenario has not been executed.
Acceptance criteria
1. Persist the completion attendance update atomically with completion where compatible with lock order, or enqueue durable, idempotent synchronization in that transaction. A transient failure must not silently leave attendance permanently stale.
2. Use Asia/Ho_Chi_Minh business dates and the persisted completion timestamp; cover same-day, midnight, multiple days, Sunday and payroll-period boundaries.
3. Exercise the actual driver completion route, then read driverWorkDays and payroll; verify repeated requests and retries neither omit days nor duplicate work-day/financial records.
4. Preserve legitimate existing trip attribution, permissions and closed-period handling. Keep direct driver completion; do not restore an approval step.
Verification coverage
CODE-READ ONLY. The source path was reviewed; the current staging deployment, UI interaction and database side effects were not exercised for this finding. Add a testplan regression before implementing and exercise the stated recovery and permission boundaries.
