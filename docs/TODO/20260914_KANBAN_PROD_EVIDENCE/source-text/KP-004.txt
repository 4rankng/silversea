Validate container identifiers before adding them to a trip
QA-060 | P2 | Bug | TODO
Environment: Staging https://vantai.tingting.vip
Reviewed: 14 September 2026
Role: OPS qa.audit.ops.0914 (QA Audit Ops 0914); Chrome phone 390 × 844
Page: https://vantai.tingting.vip/my-forwarder-trips/20
Existing behaviour
Thêm in Số Container / Seal disables Lưu for an empty Số container field, but accepts ABC without a validation warning. Saving increases the count from 1 to 2. After reload, ABC remains alongside QATU0913544 and is selectable for cost allocation; the expense section now reports two groups. The placeholder suggests a complete number such as MSKU1234567.
Target behaviour
Validate the agreed container-number format before saving and show a clear inline correction message. Normalize approved input consistently. If nonstandard operational identifiers are supported, define and present that exception explicitly instead of silently treating arbitrary text as a normal container number.
Impact
Malformed identifiers enter the operational container list and its cost-allocation choices, reducing data quality and creating ambiguous records.
Cause and investigation
Hypothesis: container creation does not enforce the intended identifier format. Client, service and persistence validation responsibilities require investigation; no specific implementation cause or check-digit requirement is established.
Steps to reproduce
1. As qa.audit.ops.0914, open /my-forwarder-trips/20 and click Thêm in Số Container / Seal. Observe that an empty Số container disables Lưu.
2. Enter ABC and the optional audit note, then save. Observe the count change from 1 to 2 without a warning.
3. Reload the page. ABC remains present and can be selected for cost allocation. Use a disposable equivalent fixture when repeating.
Acceptance criteria
1. Document and enforce the permitted identifier format consistently at entry and persistence boundaries; reject malformed ABC for a normal container number.
2. Show accessible field feedback and preserve input for correction. Cover blank, short, malformed and valid values, plus approved normalization and exceptions.
3. Rejected input creates no container or cost group; valid input saves once and remains consistent after reload across phone, tablet and desktop.
Requirement reference
Exploratory staging review, 14 September 2026; container field placeholder MSKU1234567.
